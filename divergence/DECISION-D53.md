# D53 — node7_disclosure.py built: the demo page is now generated, not hand-typed

**Date:** 21 August 2026

## The problem, stated plainly

`output-interface.html` — the page a judge looks at first, before any code
— was a hand-built mockup. Every number in it was typed by a person into an
early draft, marked with explicit `stale-ok` HTML comments once the real
pipeline overtook it (₹43,633 / 9.27% <!-- stale-ok --> instead of the real
₹47,868.76 / 10.19%; 2 methods shown instead of the real 12). `architecture.md` names
this exact failure mode as the one D38 exists to prevent — *"the headline
number must never be a token prediction"* — and a number a person typed by
hand is not better than a token prediction; it is the same failure with a
human in the loop instead of a model, and it was the one place in the whole
project doing it. `⚙ D — DISCLOSURE COMPOSER` was on the original component
list, `node7` on Step 26's own list, and was never built. `PIPELINE-FLOW.md`
already said so out loud: *"a static template, not wired to a live record
yet."*

## What was built

`node7_disclosure.py`. Deterministic — no model, no API, matching
`architecture.md`'s own spec for ⚙ D (*"A document whose purpose is to be
trustworthy cannot be produced by something that can hallucinate"*). Reads
one `run_pipeline.py` output record and renders the page. Same visual
language as the original mockup — same CSS, same ledger-book design, same
section ordering (*"absence first, the range second, a single answer
never"* — the ordering itself is `architecture.md`'s stated argument, kept
exactly) — only the content generation is new.

**Two paths, both real:**
- A case with a genuine valuation dispute (D1: 12 methods) shows the lowest
  and highest, the real spread, and a note that more were computed.
- A case with none (C1: one method, `spread.inr == 0`, D51's fix) shows a
  single confirmed figure instead of forcing a fake two-pole "range" —
  this is the false-abstention proof Block E1 built the schema amendment
  for, and now it has somewhere to actually appear.

Missing items, regime conclusions (with real certainty labels), the
provisions manifest, and `limits[]` are all pulled directly from the
record. No text in the generated page describing a fact, a figure, or a
conclusion was typed by a person.

## What ran

`python node7_disclosure.py --record runs/21aug/D1_fixed_pipeline.json`
— the corrected D1 record (D50's addendum: Rule 206 defect fixed) — now
**is** `output-interface.html`. Tested against C1's record too (the
single-method path) before committing either. Both render correctly; the
D1 version is what's live.

## What is not claimed

This does not make the underlying record more correct than it is — if
`D1_fixed_pipeline.json` still has an open finding (Rule 243(8)(e), D50's
addendum), that finding shows up verbatim in the generated page's regime
section too, exactly as it exists in the record. The composer's job is
fidelity to the record, not correctness of the record — those are two
different components (⚙ D versus 🤖 3/4), and conflating them would put a
model's mistake and a template's mistake in the same bucket, which is
precisely the distinction this project's whole architecture rests on.

## What to say about it

> "The page a judge sees first used to be the one place in this project
> where a number was typed by hand instead of generated. It isn't anymore
> — the same discipline we hold every model call to (no invented figures,
> no silent averaging) now applies to the page itself, generated by a
> deterministic script from the actual record, the same record whose
> numbers are in this results file."
